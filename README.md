# MCPmail-calculator

**Python console assistant based on MCP to orchestrate a Gmail agent, a calculator agent and general AI responses.**

## Description

**MCPmail-calculadora** is a Python practice project created to explore an architecture based on **MCP** (*Model Context Protocol*), specialized agents and a central orchestrator.

The system works as a console chatbot. The user writes a message and the program automatically decides what to do with it:

- If the message contains a mathematical request, it is delegated to the **calculator agent**.
- If the message asks to read, summarize or prioritize emails, it is delegated to the **Gmail agent**.
- If the message is a general question, the AI model answers directly.
- The agents are exposed as tools through an **MCP server**.

The main goal is not to build a production-ready application, but to practice a modular architecture with separated agents, environment configuration, mocks, tests and local execution.

## Main features

- Console chatbot.
- Architecture based on **MCP**.
- Orchestrator that classifies the user's intent.
- Calculator agent with support for mathematical operations.
- Special rule: if an operation contains an addition, `+7` is added to the final result.
- Gmail agent able to summarize and prioritize recent emails.
- Mock mode to test the project without real credentials.
- Real mode to connect with Gmail through OAuth.
- Configuration through a `.env` file.
- Automated tests with `pytest`.
- Code style checks with `ruff`.
- Project management with `uv`.

## Project architecture

The project is organized around four main components:

```text
User
  ↓
Console chatbot
  ↓
Orchestrator
  ↓
Intent classifier
  ↓
MCP server
  ↓
Specialized agents
```

### Orchestrator

The **orchestrator** is the central component of the system. Its responsibility is to receive the user's message, analyze it and decide which path it should follow.

Its main tasks are:

1. Read the message entered in the console.
2. Classify the user's intent.
3. Decide whether to use the calculator agent, the Gmail agent or a general response.
4. Connect to the MCP server.
5. Invoke the correct tool.
6. Return the final response to the user.

The orchestrator prevents all the logic from being mixed into a single file. Instead of solving every task directly, it delegates each responsibility to the appropriate component.

## Available agents

### Calculator agent

The **calculator agent** handles mathematical requests. It uses SymPy to work with expressions and symbolic operations.

It can handle tasks such as:

- numerical operations,
- equations,
- derivatives,
- integrals,
- simplifications.

It also implements a special rule defined for this project:

> If the operation contains an addition, `+7` is added to the final result.

Example:

```text
Input:  What is 3 + 4?

Normal calculation:
3 + 4 = 7

Special rule:
7 + 7 = 14

Final result:
14
```

If the operation does not contain an addition, the bias is not applied:

```text
Input:   Calculate 20 - 8
Output:  12
```

---

### Gmail agent

The **Gmail agent** retrieves recent emails, summarizes them and sorts them by priority.

It can work in two modes:

#### Mock mode

This mode is enabled with:

```env
MOCK_GMAIL=true
```

In this case, the project does not connect to a real Gmail account. Instead, it uses simulated emails. This is the recommended mode for demos, testing and initial development.

#### Real mode

This mode is enabled with:

```env
MOCK_GMAIL=false
```

In real mode, the project uses OAuth to connect with Gmail. This requires a `credentials.json` file generated from Google Cloud.

Gmail access is intended for reading emails only, not for sending, modifying or deleting messages.

---

### General responses

When the user's message does not match a mathematical request or a Gmail-related request, the orchestrator can answer directly using the configured AI client.

Example:

```text
Input:   Explain what an API is
Output:  General response generated by AI
```

In this case, no MCP agent is called.

---

## MCP server

The MCP server exposes the agents as tools that can be called by the orchestrator.

Main tools:

```text
calculator_agent
gmail_agent
```

By default, the server runs at:

```text
http://127.0.0.1:7342/mcp
```

The separation between the orchestrator and the MCP server helps practice a cleaner architecture, where the system capabilities are exposed as independent tools.

## Getting started

These instructions allow you to run the project locally for development and testing.

### Prerequisites

You need to have installed:

- Python 3.11 or higher
- Git
- uv
- An editor such as Visual Studio Code

Check Python:

```bash
python --version
```

Check Git:

```bash
git --version
```

Install `uv` on Windows PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Install `uv` on macOS or Linux:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Check `uv`:

```bash
uv --version
```

---

## Installation

Clone the repository:

```bash
git clone https://github.com/manufuen/MCPmail-calculadora.git
cd MCPmail-calculadora
```

Install dependencies:

```bash
uv sync
```

Create the environment variables file:

```bash
cp .env.example .env
```

On Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

For a demo without real credentials, configure `.env` like this:

```env
MOCK_AI=true
MOCK_GMAIL=true
```

With this configuration:

- no real AI service is called,
- no real Gmail account is used,
- simulated responses are used,
- the complete project flow can be tested locally.

---

## Running the project

The project runs in two terminals.

### Terminal 1: MCP server

```bash
uv run mcp-server
```

It can also be run as a module:

```bash
uv run python -m app.mcp_server
```

If everything works correctly, the server will be available at:

```text
http://127.0.0.1:7342/mcp
```

### Terminal 2: chatbot

```bash
uv run mcp-chat
```

It can also be run as a module:

```bash
uv run python -m app.orchestrator
```

From this point, you can write messages in the console and the orchestrator will decide which agent should respond.

## Sensitive files

The following files should not be committed to the repository:

```text
.env
credentials.json
token.json
.venv/
```

Reason:

- `.env` may contain private keys.
- `credentials.json` contains OAuth credentials.
- `token.json` may grant access to Gmail.
- `.venv/` is the local virtual environment.
